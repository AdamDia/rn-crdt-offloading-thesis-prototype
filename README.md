# RN Native CRDT Offloading Benchmark

Master thesis prototype for:
**“Efficient Offloading of CRDT-Based State Synchronization in React Native: A Swift-Backed Approach for High-Frequency UI Updates.”**

This repository contains a React Native (TypeScript) iOS-focused prototype used to compare JavaScript execution against Swift-backed native execution for lightweight synchronization and higher-frequency UI workloads.

## Final Prototype Scope
- **Primary benchmark:** JS vs Swift G-Counter interval benchmarks and deterministic burst merges
- **Dashboard workload benchmark:** JS vs Swift dashboard-derived computation under repeated UI refresh pressure
- **Supplementary validation:** LWW Register correctness and lightweight validation scenarios
- **Supplementary demonstration:** Network Link Conditioner connectivity check plus deterministic local reconnection burst demo

## Repository Structure
- `src/crdt/js/` — JavaScript CRDT implementations (`GCounter`, `LWWRegister`)
- `src/native/` — native module wrappers and CSV export bridge
- `src/metrics/` — benchmark logging, CSV export schema, shared logger
- `src/screens/` — CRDT Benchmark and Dashboard Workload screens
- `docs/` — experiment design, thesis plan, results templates, screenshots guidance
- `results/` — exported benchmark CSV files and summarized thesis data tables

## Running the Prototype

### Prerequisites
- Node.js / npm
- Xcode
- CocoaPods

### Install and launch
```bash
npm install
cd ios
pod install
cd ..
npm start
npx react-native run-ios --simulator "iPhone 17 Pro" --no-packager
```

Recommended Xcode workspace:
- `ios/RNOffloadingBenchmark.xcworkspace`

## Benchmark Tracks

### 1) Primary CRDT benchmark
- **Sustained interval runs:** `100ms`, `50ms`, `20ms`
- **Fixed duration:** `60s`
- **Modes:** `js`, `native`
- **Burst merge scenarios:** `500`, `1000`, `5000`, `10000` unique replicas

### 2) Dashboard workload benchmark
- Official scenarios:
  - `dashboard_continuous_5000_20ms`
  - `dashboard_continuous_10000_50ms`
  - `dashboard_continuous_10000_20ms`
- Each official dashboard scenario should be repeated at least **5 times per mode**.
- Manual stop is allowed for inspection only; partial runs are marked and should be excluded from official data.
- The dashboard preview uses synthetic derived signal values generated by the benchmark workload.
- These values may be positive or negative because they come from signal-style computations.
- They are not G-Counter values and are not interpreted as application business data.

### 3) Supplementary validation
- **LWW Register** is included to show that the Swift offloading path is not hardcoded to G-Counter only.
- LWW checks are supportive validation, not the main performance evidence.

### 4) Supplementary network demonstration
- The app includes a small connectivity check that reacts to Apple Network Link Conditioner settings.
- The reconnection burst demo is **deterministic and local**; it does **not** represent backend synchronization.
- This section is included for qualitative demonstration only and is not part of the primary benchmark dataset.

## CSV Export
- Exported filename: `benchmark-results.csv`
- Shared unified CSV covers CRDT runs, dashboard runs, and any supplementary demo rows that are explicitly logged
- Important columns:
  - `benchmarkCategory`
  - `scenarioName`
  - `operationCount`
  - `finalCrdtValue`
  - `averageOperationTimeMs`
  - `maxOperationTimeMs`
  - `burstMergeTimeMs`

## Measurement Notes
- All current measurements are collected on the **iOS Simulator**.
- This should be discussed as a limitation for bridge latency, native scheduling behavior, CPU behavior, and memory behavior.
- **Flipper**, if used at all, should be treated only as an optional debugging aid and **not** as a source of performance measurements for the thesis.
